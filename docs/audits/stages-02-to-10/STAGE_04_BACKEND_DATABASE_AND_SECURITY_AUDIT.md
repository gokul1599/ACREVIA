#### 3. Critical Architectural Finding: Migration DDL Pattern
- **Audit Observation:** The Alembic migration scripts call `Base.metadata.create_all(bind=bind)` inside the `upgrade()` function instead of emitting discrete autogenerated DDL (`op.create_table`, `op.add_column`).
- **Risk Assessment (Medium Severity):** For fresh environments and idempotent table provisioning, this pattern works reliably. However, it cannot execute non-destructive column renames, schema alterations, or downward rollbacks (since `downgrade()` is either a destructive `drop_all` or a no-op `pass`). This represents operational technical debt to be restructured for formal zero-downtime production migrations.

### 04.4 Multi-tenant isolation & IDOR defenses

Tenant isolation is enforced strictly at the database query level via FastAPI security dependencies:
- **Farm Access Control:** Every query checks `plot.farm.owner_id == current_user.id` or checks active membership in `farm_memberships`.
- **Automated Security Test Suite Verification (`backend/tests/test_authorization.py`):**
  - `test_owner_can_access_own_farm`: **PASSED** (Owner receives 200 OK).
  - `test_cross_farm_read_blocked`: **PASSED** (Farmer B querying Farmer A's farm receives `HTTP 403 Forbidden`).
  - `test_cross_farm_plot_creation_blocked`: **PASSED** (Farmer B creating plot on Farmer A's farm receives `HTTP 403 Forbidden`).
  - `test_cross_farm_observation_blocked`: **PASSED** (Farmer B posting observation on Farmer A's plot receives `HTTP 403 Forbidden`).
  - `test_cross_farm_observation_listing_blocked`: **PASSED** (Farmer B listing Farmer A's observations receives `HTTP 403 Forbidden`).
  - `test_admin_can_access_any_farm`: **PASSED** (Admin user receives authorized access).

**Verdict:** Zero IDOR vulnerabilities detected across audited endpoints.
